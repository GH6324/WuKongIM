# Issues #927, #928, and #929: recovery verification

Date: 2026-09-08. These results describe a local repair candidate, not a release
or a 60-minute SDK acceptance result.

## Changes and evidence

- **#927:** The released C#/JS three-node fixture reproduced a second-fault
  migration timeout. Offline copies confirmed an acknowledged message at offset
  6 on nodes 2 and 3 while node 1 ended at 5; node 2 was unavailable. Waiting for
  a pre-existing second copy prevented recovery, while truncation would lose an
  acknowledged message. Recovery now proves that every responding tail in a
  read quorum belongs to one chain, copies bounded immutable proposal pages
  without truncation, and performs a fresh quorum proof and authority barrier
  before readiness. Divergent/unstable evidence stays unavailable. The new tests
  fail on the earlier implementation and cover both possible surviving leaders,
  an empty survivor, divergent tails, and recovery over multiple bounded pages.
- **#927:** A waiting migration at the front of the task list also starved later
  tasks. The executor now attempts each task in a bounded page; active-index
  cursors rotate across owned hash slots and resume past waiting tasks.
- **#928:** The mock's RECVACK notification precedes the client's accounting
  update. The assertion now waits for the matching client's accounting
  publication. The old test reproduced the zero-count assertion under race;
  the fixed test passed 10,000 repetitions at each of CPU counts 1, 4, and 8.
- **#929:** A new UID authority no longer treats its empty, unproven directory as
  offline. Requested UIDs are reconstructed through bounded active-session
  owner queries, fenced by Slot authority and owner boot/session identity.
  Missing/partial evidence remains retryable. Cache eviction requires a new
  proof, and tombstones/newer owner sequences survive reconstruction.

The branch includes the repair work already merged through PR #923 and current
main. SDK implementation sources and published dependencies were not modified.
A later owner-membership test also covers active Controller-only nodes, since
gateway ownership does not imply the data-replica role. Full validation exposed
an unrelated coordinator test that ordered observer startup before concurrent
status reads; its comparison now preserves phase/call constraints while allowing
that scheduling difference. Production coordinator behavior is unchanged.

Harness-only commits pin the server and preserve local diagnostic evidence;
they are recorded separately below.
